## TT-003: 出題・回答画面（2026-07-30）

**実装ファイル**

- `test-app/components/exam/ExamContext.tsx` — 模擬テストのセッション状態（出題データ・現在の問題番号・回答・結果）を保持する React Context（`ExamProvider` / `useExam`）
- `test-app/components/exam/QuestionCard.tsx` — 1問分の問題文・シャッフル済み選択肢（ラジオボタン）を表示するコンポーネント
- `test-app/app/exam/layout.tsx` — `/exam` 配下（`/exam`, `/exam/result`）を `ExamProvider` でラップし、ページ遷移をまたいで state を共有できるようにするレイアウト
- `test-app/app/exam/page.tsx` — 開始画面（未開始時）＋出題・回答画面（開始後）。進捗表示（`n / 65`）、前へ／次へ、採点する（未回答があれば確認ダイアログ）を実装
- `test-app/app/exam/result/page.tsx` — 簡易プレースホルダーの結果画面（正解数・正解率のみ表示、詳細レビューは TT-004 で本実装）

**設計メモ**

- チケットでは「Context または sessionStorage」の選択肢が示されていたが、`app/exam/layout.tsx` を `/exam` と `/exam/result` の共通レイアウトにすることで React Context のみでページ遷移をまたいだ状態共有を実現（シリアライズ不要でシンプル）。リロードするとレイアウトごとマウントし直されるため、「リロード＝最初からやり直し」の仕様も自然に満たす。
- テスト中は正誤・解説を一切表示しない設計（`QuestionCard` は問題文と選択肢のみを表示）。

**確認内容**

- `npm run lint` / `npx tsc --noEmit` / `npm run build` すべて成功（`/`, `/exam`, `/exam/result` が静的ルートとして生成されることを確認）
- 開発サーバーを起動し、`curl` で以下を確認
  - `/` に「模擬テスト開始」導線があること
  - `/exam` の初期表示（未開始状態）に「模擬テスト開始」ボタンが表示されること
  - `/exam/result` に直接アクセスした場合（結果データなし）に空状態メッセージ「結果データがありません」が表示されること
- 注意: この環境では claude-in-chrome 等のブラウザ操作ツールが利用できなかったため、実際のクリック操作（回答選択・前へ/次へ・採点する→結果画面遷移）はコードレビューと `curl` によるレンダリング確認のみで、ブラウザでの目視操作確認はできていない。次回セッションでブラウザ確認が可能であれば、一連の操作フローを実際にクリックして検証することを推奨する。

**次のステップ**

- TT-004（結果画面の本実装）: `/exam/result` に問題ごとの詳細（自分の回答・正解・正誤・解説、未回答は「未回答（不正解扱い）」と明示）を実装し、現状のプレースホルダーを置き換える。

## TT-004: 結果画面の本実装（2026-07-30）

**実装ファイル**

- `test-app/components/exam/QuestionResultCard.tsx` — 1問分の詳細レビューカード。バッジ（正解／不正解／未回答（不正解扱い））、シャッフル後の並びのままの選択肢一覧（正解の選択肢に「正解」ラベル、自分が選んだ選択肢に「あなたの回答」ラベル、両方一致する場合は「正解・あなたの回答」）、解説を表示
- `test-app/app/exam/result/page.tsx` — TT-003 のプレースホルダーを置き換え。サマリー（正解数/65・正解率%）、「もう一度挑戦」ボタン（クリックで `exam.startExam()` を呼んでから `/exam` へ遷移し、確認クリック1回で新しい65問セッションを開始）、全65問分の `QuestionResultCard` 一覧を実装
- `test-app/scripts/verify-result-render.tsx` — `react-dom/server` の `renderToStaticMarkup` で `QuestionResultCard` を実際にレンダリングし、「正解を選んだ場合／不正解を選んだ場合／未回答の場合」の3パターンで期待する文言（バッジ・ラベル・解説）が出力に含まれることを検証するスクリプト（`npx tsx scripts/verify-result-render.tsx` で再実行可能）

**確認内容**

- `npm run lint` / `npx tsc --noEmit` / `npm run build` すべて成功
- `verify-result-render.tsx` で3パターン（正解／不正解／未回答）とも期待通りのバッジ・ラベル・解説文が描画されることを確認（全項目 OK）
- devサーバー起動後、`curl` で `/exam/result` の空状態（データなし）が引き続き正しく表示されることを確認
- 注意: 前回同様、この環境ではブラウザ操作ツールが使えないため、実際に65問回答→採点→結果画面で問題ごとのレビューが正しく表示されるかの**目視でのクリック確認はできていない**。`react-dom/server` によるコンポーネント単体のレンダリング検証と型・lint・build チェックで代替している。ブラウザ操作が可能な環境がある場合は、一度実際に模擬テストを最後まで解いて結果画面を目視確認することを推奨する。
- 副次的に確認: 前回セッションで `TaskStop` した devサーバーの子プロセス（Windows 上で `npm run dev` の子の `next` プロセス）が実際には終了しておらず、ポート3000を掴んだまま残っていた。今回 `taskkill` で個別に停止。Windows環境でバックグラウンドの `npm run dev` を停止する際は、`TaskStop` 後も `netstat` 等でポートが本当に解放されたか確認するのが安全。

**次のステップ**

- `test_tickets/` のスコープ（TT-001〜TT-004）はこれで一通り完了。追加でやるとすれば、実ブラウザでの一連の操作フロー（開始→回答→前後移動→採点確認ダイアログ→結果画面→もう一度挑戦）の目視確認。
- 本番版（`tickets/`）に着手する場合は、このプロトタイプの `lib/quiz/` 実装（純関数の分割方針）を参考にしつつ、未解答優先ロジックやDBアクセスを踏まえた設計に作り直す（TICKETS.md の「本番版との関係」に記載の方針どおり、そのまま流用はしない）。
