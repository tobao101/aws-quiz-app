# AWS Certified AI Practitioner 模擬テスト Web アプリ 要件定義書

- **ドキュメントバージョン**: 1.0
- **作成日**: 2026-07-02
- **対象**: AWS Certified AI Practitioner（AIF-C01）受験者向け学習・模擬試験アプリ

---

## 1. 概要

### 1.1 目的
AWS Certified AI Practitioner 試験の合格を目指す学習者が、本番形式の模擬テストと反復学習を通じて、効率的に知識の定着と弱点克服を行える Web アプリケーションを提供する。

### 1.2 スコープ
- 本番形式（65問）の模擬テスト機能
- 全問（195問プール）を1問ずつ即時採点で解く反復学習機能
- 過去の受験結果を復習できる機能（直近10回分）

### 1.3 想定ユーザー
- AWS Certified AI Practitioner の受験を予定している個人学習者
- ログインして自分の学習履歴を端末をまたいで管理したいユーザー

---

## 2. 用語定義

| 用語 | 定義 |
| --- | --- |
| 問題プール | `quiz_data.json` に含まれる全問題（現状193問、id は 1〜195 で一部欠番あり） |
| 模擬テスト | 問題プールから 65 問を抽出して実施する本番形式のテスト |
| セッション | 1 回分の模擬テストまたは学習の実施単位 |
| 未解答優先 | まだ一度も解いていない、または直近で不正解だった問題を優先的に出題する方式 |
| 選択肢シャッフル | 出題ごとに選択肢（A/B/C/D）の並び順をランダムに入れ替えること |

---

## 3. データ仕様

### 3.1 問題データ（`quiz_data.json`）
各問題は以下の構造を持つ JSON オブジェクトの配列。

```json
{
  "id": 1,
  "question": "問題文（複数行を含む場合あり）",
  "options": {
    "A": "選択肢A",
    "B": "選択肢B",
    "C": "選択肢C",
    "D": "選択肢D"
  },
  "correct_answer": "B",
  "explanation": "解説文（各選択肢の概要・参考リンクを含む）"
}
```

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | number | 問題の一意識別子（1〜195、欠番あり） |
| `question` | string | 問題文（改行 `\n` を含む場合あり） |
| `options` | object | 選択肢（キー A/B/C/D、値は選択肢テキスト） |
| `correct_answer` | string | 正解キー（"A"〜"D"） |
| `explanation` | string | 解説文 |

### 3.2 データ運用方針
- 問題データはアプリの初期セットアップ時に Supabase の `questions` テーブルへインポートする（シードスクリプトを用意）。
- 出題ロジック・履歴集計はすべて Supabase 側のデータを正とする。
- 問題数が将来増減しても対応できるよう、65問という数はプールサイズに依存しない固定値として扱う（プールが65問未満の場合は全問出題）。

### 3.3 選択肢シャッフルの扱い
- 出題時に選択肢の順序をランダムに入れ替える。
- 正解判定はキー（A/B/C/D）ではなく **選択肢テキストの一致** で行うか、シャッフル後の並びに応じて正解キーを再マッピングして保持する。
- シャッフルされた並び順は、そのセッションの回答データとして保存し、後から復習した際に出題時と同じ並びを再現できるようにする。

## 4. 機能要件

### 4.1 機能一覧

| No | 機能名 | 概要 |
| --- | --- | --- |
| F-01 | ユーザー認証 | Supabase Auth によるログイン／サインアップ |
| F-02 | 模擬テスト | 65問を本番形式で実施し、終了後に正解率・解説を表示 |
| F-03 | 全問学習モード | 195問プールを1問ずつ即時採点で反復学習 |
| F-04 | 復習機能 | 直近10回分の受験結果を再確認・復習 |
| F-05 | ダッシュボード | 学習状況・正解率推移の可視化（補助機能） |

---

### 4.2 F-01 ユーザー認証

**目的**: ユーザーごとに学習履歴を保存し、複数端末で同期できるようにする。

- 認証基盤は **Supabase Auth** を利用する。
- 認証方式（要確定）: メール＋パスワード方式を基本とし、必要に応じて OAuth（Google 等）を追加可能な構成とする。
- 未ログイン状態では模擬テスト・学習・復習機能は利用不可とし、ログイン画面へ誘導する。
- ログイン中ユーザーの情報（ユーザーID）を各種履歴データに紐付ける。
- ログアウト機能を提供する。

**受け入れ条件**
- 未ログインで保護ページにアクセスするとログイン画面にリダイレクトされる。
- ログイン後、そのユーザーの履歴のみが表示される（他ユーザーの履歴は見えない）。

---

### 4.3 F-02 模擬テスト機能

**目的**: 本番同様の形式で 65 問を解き、実力を測定する。

#### 出題ロジック
- 問題プール（195問）から **65問をランダム抽出** する。
- 抽出時は **未解答優先** とする。
  - 優先度: ① 未解答の問題 → ② 過去に不正解だった問題 → ③ 正解済みの問題、の順で抽出候補を選ぶ。
  - 未解答が65問に満たない場合は、不正解・正解済みから補充する。
- 各問題の **選択肢の順序を毎回シャッフル** する。

#### 出題・回答フロー
1. 「模擬テスト開始」で 65 問のセッションを生成する。
2. 1問ずつ、または一覧形式で回答する（1問ずつ順送りを基本とする）。
3. テスト中は **正誤・解説を表示しない**（本番形式）。
4. 未回答の問題があっても提出できる（未回答は不正解扱い）。
5. 全問回答または「採点する」操作で終了する。

#### 結果表示（テスト終了後）
- **正解率（％）** と 正解数 / 65 を表示する。
- 合否目安（例: 70% を合格ラインの目安として表示）※合格ラインは目安であり公式値ではない旨を明記。
- 各問題ごとに以下をまとめて確認できる:
  - 問題文
  - 自分の回答（シャッフル後の並びで表示）
  - 正解
  - 正誤
  - 解説
- 結果は履歴（F-04）として保存する。

**受け入れ条件**
- 開始のたびに出題される問題・選択肢順が変わる。
- 未解答の問題が優先的に出題される。
- 終了後に正解率と全問の解説が確認できる。
- 結果が復習履歴に保存される。

---

### 4.4 F-03 全問学習モード

**目的**: 問題プール全体（195問）を反復学習し、知識を定着させる。

- 形式: **1問ずつ即時採点の反復学習（フラッシュカード形式）**。
- 1問回答するごとに、即座に **正誤・正解・解説** を表示する。
- 「次の問題へ」で進む。
- 出題順は未解答優先（＋任意でランダム／id 順を切り替え可能とする）。
- 各問題の回答結果（正解／不正解）を記録し、模擬テスト（F-02）の未解答優先ロジックにも反映する。
- 中断・再開ができるよう、進捗を保存する。

**受け入れ条件**
- 回答直後に解説が表示される。
- 解いた問題の正誤が履歴・進捗に反映される。
- 中断後に再開できる。

---

### 4.5 F-04 復習機能

**目的**: 過去の受験結果を振り返り、間違えた問題を復習する。

- 直近 **10回分** の模擬テストセッションを一覧表示する。
- 各セッションについて以下を表示:
  - 実施日時
  - 正解率 / 正解数
  - 所要時間（任意）
- セッションを選択すると、そのときの各問題の詳細（問題文・自分の回答・正解・解説・当時の選択肢並び順）を確認できる。
- 「間違えた問題だけを復習」フィルタを提供する。
- 11回目以降の古いセッションは一覧から除外する（データ自体の削除有無は運用方針で決定）。

**受け入れ条件**
- 直近10回分のセッションが新しい順に表示される。
- 各セッションの問題ごとの正誤・解説が確認できる。
- 間違えた問題のみに絞り込める。

---

### 4.6 F-05 ダッシュボード（補助機能）

**目的**: 学習状況を可視化しモチベーションを維持する。

- 総回答数 / 全問題数（進捗率）
- 直近の正解率推移（グラフ）
- 未解答・要復習（不正解）問題数
- 「模擬テスト開始」「全問学習」「復習」への導線

※ MVP（最小構成）では必須ではなく、第2フェーズでの実装も可とする。

## 5. 非機能要件

| 分類 | 要件 |
| --- | --- |
| パフォーマンス | 出題・採点処理は体感1秒以内。問題データはキャッシュを活用する。 |
| セキュリティ | Supabase RLS（Row Level Security）でユーザーごとにデータを分離する。 |
| 可用性 | Vercel + Supabase のマネージド構成で運用する。 |
| レスポンシブ | PC・タブレット・スマートフォンで利用可能なレスポンシブUI。 |
| アクセシビリティ | キーボード操作・十分なコントラストを確保する。 |
| 国際化 | 日本語UIを基本とする（問題データが日本語のため）。 |

## 6. 技術スタック

| 分類 | 技術 |
| --- | --- |
| フロントエンド | Next.js（App Router） / React / TypeScript |
| スタイリング | Tailwind CSS（想定・要確定） |
| バックエンド / DB | Supabase（PostgreSQL） |
| 認証 | Supabase Auth |
| データアクセス | Supabase JS Client / Server Components / Server Actions |
| ホスティング | Vercel（想定） |

### 6.1 アーキテクチャ方針
- Next.js App Router の **Server Components / Server Actions** を活用し、機密情報を含む処理はサーバー側で行う。
- Supabase への書き込み（回答保存・セッション作成）は Server Action もしくは Route Handler 経由で行う。
- クライアント側では回答UIの状態管理のみを担当する。
- Row Level Security により、各ユーザーは自分のデータのみアクセス可能とする。

## 7. データベース設計（Supabase / PostgreSQL）

### 7.1 テーブル一覧

#### `questions`（問題マスタ）
| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | int (PK) | 問題ID（`quiz_data.json` の id と一致） |
| `question` | text | 問題文 |
| `options` | jsonb | 選択肢（{A,B,C,D}） |
| `correct_answer` | text | 正解キー（A〜D） |
| `explanation` | text | 解説 |
| `created_at` | timestamptz | 作成日時 |

#### `quiz_sessions`（受験セッション）
| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | uuid (PK) | セッションID |
| `user_id` | uuid (FK→auth.users) | 実施ユーザー |
| `mode` | text | `mock`（模擬テスト） / `study`（全問学習） |
| `total_questions` | int | 出題数（模擬テストは65） |
| `correct_count` | int | 正解数 |
| `score_rate` | numeric | 正解率（％） |
| `started_at` | timestamptz | 開始日時 |
| `finished_at` | timestamptz | 終了日時（null=進行中） |

#### `session_answers`（セッション内の各回答）
| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | uuid (PK) | 回答ID |
| `session_id` | uuid (FK→quiz_sessions) | セッションID |
| `question_id` | int (FK→questions) | 問題ID |
| `shuffled_options` | jsonb | シャッフル後の選択肢並び（復習時の再現用） |
| `selected_answer` | text | ユーザーの回答（null=未回答） |
| `is_correct` | boolean | 正誤 |
| `answered_at` | timestamptz | 回答日時 |

#### `user_question_stats`（ユーザー×問題の学習状況／出題優先度用）
| カラム | 型 | 説明 |
| --- | --- | --- |
| `user_id` | uuid (FK→auth.users) | ユーザー |
| `question_id` | int (FK→questions) | 問題ID |
| `attempts` | int | 回答回数 |
| `correct_count` | int | 正解回数 |
| `last_result` | boolean | 直近の正誤 |
| `last_answered_at` | timestamptz | 最終回答日時 |

- PK: (`user_id`, `question_id`)
- 未解答優先ロジックは本テーブルを参照する（レコードが無い＝未解答）。

### 7.2 RLS ポリシー方針
- `questions`: 全ログインユーザーが読み取り可能（書き込みは管理者のみ）。
- `quiz_sessions` / `session_answers` / `user_question_stats`: `user_id = auth.uid()` の行のみ本人が読み書き可能。

## 9. 出題優先度ロジック（詳細）

模擬テスト（F-02）で 65 問を抽出する際の優先度:

1. **未解答**（`user_question_stats` にレコードが無い問題）
2. **要復習**（`last_result = false` の問題）
3. **正解済み**（`last_result = true` の問題、`last_answered_at` が古い順）

- 各優先度グループ内ではランダムに選ぶ。
- 上位グループだけで65問に達しない場合、下位グループから補充する。
- これにより「まだ解いていない問題」「間違えた問題」を優先的に復習できる。
